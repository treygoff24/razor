# Live calls

A client, such as a phone app, places a live call to a session: the person talks, OpenAI's GPT-Live is the voice, and the session's own agent does the work. This page is Razor's half: the route, the relay to GPT-Live, the record and the spending.

```rust
/// Authenticated local upgrade; operational refusals are closed lines after upgrade; revocation ends it.
pub(super) async fn upgrade(State(app): State<App>, Path(id): Path<SessionId>,
    Extension(gone): Extension<Gone>, ws: WebSocketUpgrade) -> Response;
/// `[live]`, a machine key: a stand-in or relay URL, and the names the voice will hear.
pub struct LiveSettings { pub url: Option<String>, pub names: Vec<String> }
/// A fact of a live call; it never starts a turn.
Body += VoiceCall { call: String, #[serde(flatten)] event: CallEvent };
#[serde(tag = "event", rename_all = "snake_case")]
pub enum CallEvent { Started, Line { who: Speaker, text: String, start_ms: u64, end_ms: u64 }, Ended { reason: CallReason } }
pub enum Speaker { Person, Voice }
pub enum CallReason { Ended, Idle, Cap, Key, Lost, Error }
/// Set only on a hand-off, whose text is the person's words in these lines.
Input += voice_call: Option<Box<VoiceCallInput>>;
pub struct VoiceCallInput { pub id: String, pub lines: Vec<EntryId> }
/// Unread call facts, each with whether it is a line: the newest 256 lines and every start and end
/// among the newest 512 facts, and how many older ones were left out.
Summary += { voice_calls: Vec<(EntryId, bool)>, voice_calls_left_out: usize };
/// Returns once `shutdown` does and the live calls have ended, or 20 seconds have passed.
pub async fn api::serve(..., shutdown: impl Future<Output = ()>) -> Result<(), Error>;
/// OPENAI_API_KEY or live.url, and provider_only off; left out otherwise.
Server += call: bool;
/// The owner's daily count and the person's limit, if any; a reservation's `seconds` charges a
/// call at $0.05 a minute.
VoiceSettings += { call_voice: String, call_daily_dollars: Option<f64>, call_used_today: f64 };
Reserve += seconds: f64;
/// Machine keys: the model and effort of a session started for a call; "terra" and low.
Config += { call_model: String, call_effort: Effort };
/// `POST /v1/sessions`: started for a call, so a model or effort left out is the call's.
Create += call: bool;
/// `GET /v1/models`: the call's model and effort, so the phone can show them as Razor's.
Models += { call_model: Option<String>, call_effort: Option<Effort> };
```

**The call's model.** A call to a session already under way talks to that session's agent on its own model. A call started from nothing (the phone's Talk) first makes a session with `POST /v1/sessions` and `"call": true`, and the server fills in what the request leaves out from `call_model` and `call_effort`, which default to Terra at low effort (Trey, 2026-11-03: "they're all on Terra Low", from a benchmark of short assistant tasks, where Terra at low effort scored 10 of 10 and its first words reached the voice in a median 3.4 seconds); a model or effort the request names wins, and an unknown or unready call model is refused at creation with the same sentence as a named one. The server applies the default, rather than the phone reading it and sending it, so the rule lives once beside the other creation defaults and any client that starts a session for a call gets it without a copy; the phone only reads the two values from `GET /v1/models` to show them as Razor's. The keys are the person's own, like `[live]`, because the server reads them from its own settings, not a project's.

**Pacing.** Trey, 2026-11-06: "It should use whatever sentence length the situation benefits." "It's just sharp, clear. Think like Richard Feynman in terms of how clear it is at communicating complex ideas in very simple terms or very direct terms." "There's too many updates, too much narration, too chatty." "On three, let's change the automatic still working reminders to a minute. We'll start there. I do want to keep them." "The call should only end after 15 quiet minutes, not three." The agent speaks for meaningful findings, consequential changes, problems and decisions; the voice acknowledges the request, while routine work can go on in silence.

**Phone wire.** Binary PCM16 mono 24 kHz little-endian both ways. The phone sends JSON `mute`, `unmute`, `end` and `{"type":"choose","model":"astra","effort":"high"}`, either field optional. Razor sends `{"type":"ready","today":0.42,"cap":10,"model":"gpt-6.1-sol","effort":"medium"}`, the session's own model and effort (`cap` is null without a daily limit), then `{"type":"working","on":false}`, `{"type":"caption","who":"person","text":"<original delta>","start_ms":0,"end_ms":100}`, `{"type":"working","on":true}`, `{"type":"usage","seconds":95,"today":0.5}` after each charge, `{"type":"hush"}` when the person asks the voice for quiet (the phone drops the voice's audio it has queued and not yet played; no voice audio or captions follow until the person says anything else), `{"type":"chose","model":"gpt-6-astra","effort":"high"}` for each choice it holds, with the model's canonical id and null for a field left out, or `{"type":"refused","sentence":"…"}`, one sentence, after which the choice held before stays, and last `{"type":"closed","reason":"ended","sentence":"The call ended."}`. A choice is checked as an input naming it would be, the model's credentials included, in the worker's order, so its answer follows `ready` and a hand-off after it carries it; a later choice replaces it, one with neither field clears it, and the next hand-off takes it, after which the session's own model and effort hold, as after a terminal's staged choice. A hand-off the session refuses for its choice (say, the session switched to Fast since) goes without it, and the phone gets `refused`: an optional choice never costs the person their words, which wait for the next hand-off until one is admitted. A model switch is no turn of its own: a hand-off carrying a choice joins a running turn at its next tool boundary like any of the person's words, and the choice takes over at the next turn (Trey, 2026-11-04); a switch's rebuilt request ends with the person's words (`deliver` sends the rebuild's context ahead of them), so its first words answer the person. Authentication fails with 401; every other refusal upgrades, sends `closed` and closes. The route is registered after the peers forwarding layer, so a call is always to the phone's own pairing.

**Entries.** `{"kind":"voice_call","call":"live_abc","event":"started"}`, then one `line` per utterance with `who`, `text`, `start_ms` and `end_ms`, then `{"event":"ended","reason":"ended"}`; `call` is GPT-Live's session id. A hand-off is an ordinary person input with `"voice_call":{"id":"live_abc","lines":[12]}` and any held choice's `model` and `effort`; it settles open message questions as any person message does.

**Data flow.** The relay is one loop that owns both sockets and every clock, and one worker task that does every write in order, so the loop never waits on the record or the day's spending.

1. Opening refuses at once with `provider_only` on, then reads the session's summary, then `OPENAI_API_KEY`, from keys.toml or the environment (refused `key` without one unless `live.url` is set; the key goes wherever the call goes), then the owner's settings (refused `cap` at the cap, when one is set). It attaches to the session's lines from its last entry, seeds the voice with a developer line naming the agent and its headline (else its title), then the newest person inputs, replies and open questions as typed text parts, at most 128 messages and 8,192 bytes, and sends `session.start` with the prompt from `call.toml` and client delegation whose automatic acknowledgement waits 800 ms, the most GPT-Live allows. A 401 or 403 handshake is `key`; an endpoint that never answers within 15 seconds is `lost`; an `error` before `session.started` is `error`, logged.
2. The worker records `Started`, and the phone hears `ready` and whether the agent is already working.
3. Phone frames go to `session.input_audio.append` one at a time, empty ones dropped; mute and unmute go on unacknowledged. GPT-Live's audio goes to the phone as it comes.
4. Each transcript delta is a caption at once, whole, and joins the current utterance until the other speaker talks, a hand-off, a two-second pause, 4 KiB, or the end; a longer delta is cut at character boundaries into lines of 4 KiB. The worker records each utterance as one line.
5. A delegation flushes the utterance. With the agent idle, the voice is given commentary asking it to say in a few words that it is looking into the request, naming it (left alone, GPT-Live's own acknowledgement was generic: "Good question, let me check"); the request is the step a quiet stretch names until the agent describes one; and the worker is asked to admit the person's lines since the last hand-off as one input, leaving out requests for quiet, which are for the voice. A delegation that comes before any line, with the agent idle, waits for the next person line begun by its `offset_ms` in GPT-Live's audio; a line begun later is not admitted, so GPT-Live's late hand-off of words already sent does not admit the small talk after it. While the agent works, the person's lines go to it once they have paused for two seconds, as one input however often the voice talked over them, so a correction reaches the agent whether or not GPT-Live hands it off, and a delegation then adds nothing; the loop's clock waits out the person's talking rather than spinning on it. A line only of backchannel (mm, hm, mhm, uh, huh, yeah, okay, ok, right) is not sent on its own; it goes with the next line that is. Lines still waiting when the agent's turn ends go at once as the next turn's input, and the call stays working; with the person still speaking, it stays working until their pause, and then sends what is waiting, or ends the work if nothing is. Nothing begun after a turn's end is admitted this way. The draft is untouched.
6. The session's lines drive the voice: the agent's text is said as commentary in pieces of at most 500 bytes cut at sentence ends; its question to the person is said; each other step's `description` is kept, and after one minute in which nobody spoke and the voice was given nothing while it works and is not held, the voice is asked to say it is still working on the latest one, once per call for each step; after one more such minute on the same step, or a minute on a step already said, it is asked once to say in a few words that it is still on it. A step without a description gives nothing. Steps go to GPT-Live only that way: given as silent thinking, a burst of three was read aloud ("Work. Family. That's all three."). One clock serves this and the idle close: the last speech, words given to the voice, hand-off or turn end.
7. A person's utterance made only of words that ask for quiet holds the voice: at least one of stop, wait, hold, hang, pause, shh, quiet, enough or sec, and otherwise only on, up, a, one, second, moment, minute, just, please, okay, no, sorry or talking ("wait", "no, stop", "hold on a second"; not "don't stop" or "wait, which file?"). It is judged as each fragment of the person's words arrives, so "wait" holds at once and "wait, which file?" lets go at its next word. While held, the phone gets `hush` and none of the voice's audio, the voice's words are neither captioned nor recorded, and the agent's text and questions are kept, at most 8 KiB; past that the rest is left out of what the voice is given, and the record keeps all of it. Anything else the person says lifts the hold (a blank fragment, which GPT-Live sometimes sends, does not), and the kept words go to the voice as thinking, so it answers from the start of what the agent said rather than from words the person never heard. The agent's work never stops for a hold.
8. Unread facts reach the model ahead of every batch it is sent, from `deliver` and `rebuild` alike, as one input; the turn's end answers them. The model sees every start and end, the newest lines (both speakers') within 256 and 64 KiB, and one line saying how many earlier lines were left out; the record keeps them all. A start says the person is on a call only when this server process started it, so a call a crash or restart cut off reads as no longer running. A hand-off's lines leave the unread list when it is recorded, so its words are read once. Rebuilt contexts render no call entries, so a rebuild sends the unread facts again.
9. The worker charges the most seconds GPT-Live has reported (`session.usage.updated`, then `session.closed`) beyond those already paid, through the owner's reserve; a failed charge waits for the next report, and the call's end waits for two more tries a second apart. A charge whose answer was lost may be paid twice: the count is a cap, and over is the safe direction. A call GPT-Live never metered is charged its length by the clock, from opening to close. Each charge is reported back as `usage`; at the cap the voice is given one sentence, five seconds pass, and the call closes.
10. The call ends on `end`, the phone's socket closing (`lost` if it failed), fifteen minutes with no speech and no turn running (the clock restarts when a turn ends), the cap, or revocation: `session.close`, then up to fifteen seconds for `session.closed` and its usage, the utterance flushed, `Ended` recorded, `closed` sent, and the phone read to its own close, so a phone still streaming audio gets the reason rather than a reset socket. GPT-Live's loss ends the call `lost` while the agent goes on; a socket that takes nothing for five seconds is lost. The server's stop ends every call `lost` the same way, and the process exits once they have ended or 20 seconds have passed.
11. `flows/live.py` is the stand-in: `serve(script, capture, refuse=)` and `python3 flows/live.py --port N [--script events.json] [--capture DIR] [--refuse STATUS]`. It answers what GPT-Live refuses (an initial message that is not one typed text part, an acknowledgement delay outside 0 to 800 ms, an update whose delegation is not null or an id or whose content is not a string) with an error and ends the call, so a flow sending one fails; plays script events in order (`after` waits for a command, `delay`, `audio` in 20 ms frames at real time or `pace` seconds apart, `drop` cuts the connection with no close), acknowledges appends and mute, answers `session.close` with the latest usage, and `--refuse` answers the handshake with an HTTP status.

**Hard decision.** One loop for both sockets, with the writes on a worker, against three concurrent tasks sharing mutex-guarded socket halves and an event channel, which an earlier version used. The loop owns every piece of the call's state without locks; its only waits are on the sockets themselves, each bounded at five seconds; and one computed deadline replaces a 250 ms polling timer. The worker keeps the record's order (a line before the hand-off that names it) and the spending off the loop, and its end is the call's end, so final usage needs no separate drain.

**Contract limits.** Empty `call_voice` is Marin. In four real test calls (7 to 205 seconds) the person's transcript arrived before each delegation; `session.usage.updated` came every 15 seconds from the 14th, so a call shorter than that is charged from `session.closed`, or by the clock when its connection to GPT-Live drops, and a longer call that drops is charged to its last update. An append's acknowledgement never confirms playback, so the cap's sentence gets five seconds.

**Real calls.** One answered the agent's open question by voice and then dropped the phone's socket (6 seconds, charged from the final usage); one cut GPT-Live's connection six seconds after the hand-off (9 seconds by GPT-Live's own close, ended `lost`, uncharged); one ran an 18-second command, whose plain line the voice said as "It's still running" ten seconds after the hand-off (that build timed the step from the hand-off alone; the shipped clock also waits out the voice's own words), said the reply, and closed idle three minutes later (205 seconds, charged across midnight to both days); one ended from a phone still streaming, after the idle call had shown its `closed` lost to a reset socket (7 seconds).

**Tuning calls (2026-11-02).** Eighteen real calls with flite speech and the agent on the stand-in, 464 seconds in all. With "wait, stop" said before the agent's long answer arrived, the first build gave that answer as thinking during the hold: GPT-Live spoke it at once, unheard, and after "what did you find?" went on from its middle. Keeping the words until the hold lifts, two calls held 17 to 18 seconds of silence through the late answer with no voice output at all, then answered from the start; two calls stopped mid-answer resumed on "go on". "Wait" reached Razor about 1.5 seconds after the person began, by which time GPT-Live had usually stopped its own audio. "What are you working on" was handed off in both calls. The correction was handed off in four of six calls with these settings and in all three with either receipt change alone or neither, but both misses were the test's: its agent said it was checking the script instead 1.2 and 1.4 seconds after the person's last word, before GPT-Live had handed the correction off. In forty more calls (767 seconds) the agent's first words came 1.8 seconds after the hand-off, as a model's would, and nothing more from it until the call ended: the correction was handed off in 14 of 16 with both receipt changes, 6 of 8 with neither, and 13 of 16 with both and a cancelling update that was not empty, so GPT-Live misses about one correction in six whatever the receipts. With neither change the voice opened all 14 hand-offs with its own acknowledgement ("Sure", "Got it", "Mhm"); with both it said nothing before the agent's words in 57 of 59.

axum's `ws` feature and tokio-tungstenite 0.29 (with `connect` and `rustls-tls-native-roots`) replace handwritten WebSocket framing and share one tungstenite; Python websockets 16.0 serves the stand-in.

## Meeting facts

The call-facts path also carries phone meetings, with `source: "meeting"`; an absent source remains a call. `Started` has an optional folder and recording device, `Line` has an optional name beside its small copyable `Speaker` (`Room` for meetings), `Named` records a confirmed name, and the meeting reasons are `stopped` and `canceled`. Ordinary call bytes and wording are unchanged. Meetings retain their active start across a Razor restart; only an end fact ends the live-meeting context. The folder reader never starts a turn. `Input.meeting` marks the one notes input when meetrec writes `final.json`, using the meeting's id as the input request and the recording phone as device.
