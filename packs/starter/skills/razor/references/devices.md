# Devices and notifications

Servers and the phone and Mac apps pair by code and then reach each other by key over encrypted connections; no address, VPN or open port is involved. `razor devices add <name>` shows a single-use code and waits; another server takes it with `razor devices join <name>`, an app by scanning or pasting it. `razor devices add <name> --key <key>` enrolls a program on this machine's socket instead. Read `machines.md` for pairing, `relay.md` for a relay of the person's own (`network.relays` is set before pairing), `security.md` for what a paired device may do, and `configuration.md` for notifications. Each Razor home has its own server, settings and network key. A code is a secret: let the person show or carry it, never put it in a record or message. A pair from an earlier version is paired again once by code under its old name.

The starter pack's `notify` and `ask` programs show desktop notifications. Its commented ntfy examples can send them to a phone; copy the chosen lines into the person's config and use a private, unguessable topic. A question still waits for an answer in Razor. A program named by `ask` can answer by printing a response and exiting successfully, so check its output and behavior before configuring it. Both programs run without a shell and get the sender in `RAZOR_SESSION`, `RAZOR_NAME` and `RAZOR_PROJECT`, and a question's entry in `RAZOR_ASK`; read `configuration.md`, Notifications, before writing one. Test delivery with the person's permission and avoid sending sensitive text to an untrusted service.
