# Bringing setup over from other agents

Inventory first: ask which agents the person uses, then list their MCP servers, skills, plugins, custom tools, hooks and commands from the files below, and say which carry over, how, and which do not. Write nothing until they agree. Show `razor mcp import <file>` output as the preview; settings change only when they approve. Secrets stay where they are: never copy a key, token or literal secret into a Razor settings file, command argument, message or record. The person enters it themselves, as the models and keys reference describes. Afterward check `/mcp` and a new conversation's skill list.

## MCP servers

`razor mcp import <file> [--scope global|project|private]`, run from the project's folder, prints `Add`, `Replace`, `Needs a value` and `Error` lines and writes nothing; the person applies it with `/mcp import <file>` in the terminal app and Enter. It reads JSON, or TOML when the name ends in `.toml`, with servers under `mcpServers`, `mcp_servers` or `mcp`, plus Claude Code's entries for the current project in `~/.claude.json`. Comments or trailing commas stop it. Without `--scope` it writes the project's private file; another agent's user-level servers usually belong in `--scope global`. It copies a command and its arguments (OpenCode's single command array too), a `url`, `enabled`, `tools` and `timeout`, and turns Codex's `tool_timeout_sec` into milliseconds. A header written as `${NAME}` or `{env:NAME}` becomes a reference to that variable, as do Codex's `env_http_headers`; an environment entry naming its own variable (`"X": "${X}"`) is dropped, since the server inherits Razor's environment. Any other header or environment value, such as `Bearer ${NAME}`, `$NAME`, `!command` or a literal, and Codex's `bearer_token_env_var`, is left out as `Needs a value`. It drops `cwd`, `type`, Codex's `enabled_tools`, `disabled_tools` and `env_vars`, and OpenCode's `disabled`.

Then fix what the import gets wrong. Razor's `timeout` is milliseconds: pi and Code Puppy write seconds, so a `30` from them becomes 30 ms; set it in milliseconds or remove it. Razor speaks Streamable HTTP, not the older SSE: for an entry of `type` `sse`, find the server's Streamable HTTP address, often ending `/mcp` instead of `/sse`. Razor expands no `~`, `${…}` or plugin-root variable in a command or its arguments; use absolute paths. To supply a missing value, re-add the server whole with `razor mcp add <name> --scope <scope> --config '<JSON>'`: an HTTP header is `{"env": "VAR"}` or `{"file": "path"}`, holding the whole header value (`Bearer …` included); `VAR` comes from Razor's server environment, which includes `keys.toml`. A program-run server inherits the server's environment except the names `keys.toml` lists, so a secret it needs is exported where the server starts (the service's `[server] wrapper` script, for one), or its `command` is a small script that reads a private file and starts the real server.

## Skills

Razor already loads `~/.agents/skills`, `~/.claude/skills`, `~/.codex/skills` and a project's `.agents/skills` and `.claude/skills`. For another folder, `razor config set skills '[…]'` with absolute or `~/` paths; the list replaces the old one, so include its entries (`razor config get skills`). Razor finds only `<folder>/<name>/SKILL.md`, one level down, named by its folder: move a flat `<name>.md` skill or a nested one into that shape in a folder of the person's choosing, such as `~/.agents/skills`, keeping the `name` and `description` front matter. A slash command or prompt template that is a Markdown prompt becomes a skill the same way; its argument placeholders are not filled in.

## Where each agent keeps them

- **Claude Code**: MCP servers in `~/.claude.json` (top-level `mcpServers`, and `projects.<path>.mcpServers` per project) and a project's `.mcp.json`; commands in `~/.claude/commands` and `.claude/commands`; subagents in `~/.claude/agents` and `.claude/agents`; hooks under `hooks` in `~/.claude/settings.json` and `.claude/settings.json`. Plugins are under `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/`; `installed_plugins.json` beside `cache` gives each `installPath`, and `enabledPlugins` in the settings says which are on. A plugin holds `skills/`, `commands/`, `agents/`, `hooks/hooks.json`, `.mcp.json` (more servers can be inline under `mcpServers` in `.claude-plugin/plugin.json`) and `bin/`. Copy its skills rather than pointing `skills` at the version folder, which changes with each update, and replace `${CLAUDE_PLUGIN_ROOT}` with the plugin's path before importing its servers.
- **Codex**: MCP servers as `[mcp_servers.<name>]` in `~/.codex/config.toml` (`$CODEX_HOME` moves it) and a project's `.codex/config.toml`; admin skills in `/etc/codex/skills`. Plugins are under `~/.codex/plugins/cache/<marketplace>/<plugin>/<version>/`, enabled as `[plugins."<plugin>@<marketplace>"]` in `config.toml`; the manifest, usually `.codex-plugin/plugin.json`, names its `skills` folder (by default `skills/`), its `mcpServers` file (usually `.mcp.json`), `hooks` and `apps`. Apps are ChatGPT connectors with no Razor equivalent.
- **OpenCode**: `~/.config/opencode/opencode.json` or `.jsonc`, and a project's `opencode.json(c)` or `.opencode/opencode.json(c)`. Version 1 keeps servers directly under `mcp`, which imports. Version 2 nests them under `mcp.servers` with `disabled` and an object `timeout`, which the import refuses: write a plain-JSON copy, for example `jq '{mcp: (.mcp.servers | map_values(del(.timeout, .disabled)))}'`, import that, and leave off any server that was disabled. Skills are in `~/.config/opencode/skills` and `.opencode/skills`, plus folders or addresses its `skills` setting lists; commands in `~/.config/opencode/commands` and `.opencode/commands`; plugins in `~/.config/opencode/plugins`, `.opencode/plugins` and packages its `plugins` setting names; version 1 custom tools in `.opencode/tools` and `~/.config/opencode/tools`.
- **pi**: MCP servers under `mcpServers` in `~/.pi/agent/mcp.json` and `.pi/mcp.json` (`PI_CODING_AGENT_DIR` moves `~/.pi/agent`). Skills in `~/.pi/agent/skills`, `.pi/skills` and folders the `skills` setting lists in `~/.pi/agent/settings.json` or `.pi/settings.json`; pi searches them at any depth. Prompt templates in `~/.pi/agent/prompts`; extensions, TypeScript code, in `~/.pi/agent/extensions` and `.pi/extensions`. `pi list` names installed packages, which can carry `skills/`, `prompts/` and `extensions/`; git packages are under `~/.pi/agent/git/`.
- **Code Puppy**: MCP servers under `mcp_servers` in `~/.code_puppy/mcp_servers.json` (under `$XDG_CONFIG_HOME/code_puppy` when that is set) and a project's `.code_puppy/mcp_servers.json`; an entry with no `type` is SSE. Skills in the `skill_directories` setting of `~/.code_puppy/puppy.cfg`, by default `~/.code_puppy/skills` and `./skills`; agents as JSON in `~/.code_puppy/agents` and `.code_puppy/agents`; Python plugins in `~/.code_puppy/plugins` and `.code_puppy/plugins`; hooks in `~/.code_puppy/hooks.json` and a project's `.claude/settings.json`.

Locations move between versions. When a file is missing, read the agent's own documentation or `--help`, or its list commands (`claude mcp list`, `codex mcp list`, `opencode mcp list`, `pi mcp list`, `pi list`).

## Any other agent

For an agent not listed, including a private one, find its folders: `~/.<name>`, `~/.config/<name>`, `$XDG_CONFIG_HOME`, a project's `.<name>/`, and the paths its documentation, `--help` or source names. An MCP server is an entry with a `command` and `args`, or a `url` with `headers`, often with `env`. If its servers sit under one of the three keys above, import the file; otherwise write a scratch JSON file of `{"mcpServers": {"<name>": {…}}}` using `command`, `args`, `url` and `headers`, references for secrets, and `timeout` in milliseconds, and import that, so the preview still holds back anything literal. A folder of `<name>/SKILL.md` folders is a skills folder. Anything else that runs as code inside it is a plugin or tool.

## What does not carry over as is

Code written against another agent's own interface does not run in Razor: plugins, extensions, custom tools, hooks, subagent definitions and editor or interface add-ons. For each one the person wants, read what it does and propose one of these before writing anything:

- A tool whose logic can run on its own: a script tool, `[tools.<name>]`, reading JSON input on standard input and printing its result; several related tools, or one that keeps state or a connection: a small MCP server, added with `razor mcp add`.
- A program the agent should run when a task calls for it: a command-line program plus a skill that says when and how to use it.
- A hook that checks, changes or refuses a prompt, a message, a tool call or a rebuild: a Razor plugin program with `before` or `after` (`configuration.md` under Plugins, `design/extensions.md`). Rewrite it for Razor's event JSON and exit rule: exit 0 allows, any other exit refuses with standard error as the reason, where Claude Code blocks on exit 2 or a JSON decision.
- A subagent's prompt: a skill, or the brief an agent gives a helper.
- Anything tied to the other agent's screen, keys, themes, model providers or events Razor lacks: tell the person it has no equivalent.
