# Troubleshooting and updates

Start with `razor doctor`, then read the matching section of `troubleshooting.md`. Doctor checks settings and model routes, reports key presence without values and starts no server; its Claude check can create Claude's own files, and on macOS it may offer to request desktop permissions. Its Desktop line says whether the Cua Driver daemon that `cua-driver` calls need answers; the server runs it only on a Mac where Razor has Accessibility or on Linux with `DISPLAY` set, and `server.log` says why one stopped. For details inspect `$RAZOR_HOME/server.log` and, for a Linux service, `journalctl --user -u <service>` (the home's folder name without its leading dot). A session's `startup.md` shows its opening; `/startup` shows it in the terminal. Avoid disclosing keys or private record contents.

Identify the actual Razor home and running server before acting. `command -v razor` identifies the command on the current shell's PATH, and `razor --version` prints its installed version; these may differ from the binary running the server. `lsof -t $RAZOR_HOME/server.log` (or the service's main PID) identifies the server process. On Linux inspect the server process executable via `/proc/<pid>/exe`; on macOS inspect the server process's executable with `lsof`. Compare its resolved path with the selected install and version. Check the service configuration and logs if the server is service-managed.

A restart interrupts working turns, including your own; ask the person before `razor restart` unless already authorized. Working sessions with a recent last entry resume automatically; older ones show interrupted and need input or `/continue all`. Background commands can survive the stop. `keys.toml` needs a restart; most settings do not, `network.relays` included. A paired server or app that reaches nothing after an update from before pairing by code needs pairing again (`machines.md`); doctor's network lines show this server's key, its relay and each pair's path.

`release_updates` controls automatic release downloads. With `provider_only` on, Razor downloads no release on its own, but `razor update` explicitly requested by the person still runs. A downloaded release takes effect after restart; source builds do not automatically update. Read `troubleshooting.md` for update failures and `configuration.md` for current options. Do not restart another home or replace a running binary as a diagnostic shortcut.
